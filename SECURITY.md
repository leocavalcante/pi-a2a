# Security policy

## Supported versions

Only the latest release receives security fixes. Upgrade before you report an issue because older versions may still be affected.

## Report a vulnerability

Report vulnerabilities privately through [GitHub's vulnerability reporting form](https://github.com/leocavalcante/pi-a2a/security/advisories/new). Do not open a public issue, discussion, or pull request for them.

Include:

- the affected pi-a2a version, your Pi version, Pi Durable version if you use it, Node.js version, and operating system
- what an attacker can do and safe steps to reproduce the issue

Leave out credentials, tokens, private agent endpoints, prompts, session data, attachments, logs, and project files. Use synthetic or redacted examples instead.

Please give the maintainer time to investigate and release a fix before you disclose the issue publicly.

## Exposed credentials

If a credential was exposed, revoke or rotate it with its provider first, then report how it was exposed. Never include the credential itself.
